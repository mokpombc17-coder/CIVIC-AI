# Chat room 재진입 읽은 위치 이동

참여 중인 채팅방 화면에 다시 들어올 때 마지막으로 읽은 위치를 여는 흐름과 읽음 보고 정책을 기록한다.
메시지 viewport의 스크롤 위치 모델은 `chat-message-viewport.md`를 따른다. 구현이 이 문서와 달라지면
문서를 함께 갱신한다.

## 용어

- 재진입: 이미 참여 중인 방을 목록이나 알림에서 다시 여는 화면 진입. 멤버십은 바뀌지 않는다.
- 재참여: 방을 나갔다가 다시 참여하는 것. 볼 수 있는 메시지가 새 참여 시점 이후로 바뀐다
  (`messageVisibleAfterSequence`).
- 읽은 위치: 서버에 저장된 마지막으로 읽은 순번(`storedLastReadSequence`)과 볼 수 있는 경계 중 더
  뒤쪽 순번. 현재 `resolveChatRoomEntryReadPosition`이 `entryReadThroughSequence`로 계산한다.
- 메시지 목록: 채팅방의 메시지 영역. 하나뿐이고, 아래 두 상태 중 하나를 보여 준다.
- 최신 대화: 최신 메시지부터 이어서 불러와 보여 주는 상태. 새 메시지가 실시간으로 붙는다.
- 이동한 대화: 검색 결과나 읽은 위치로 이동해 그 메시지 주변만 따로 불러와 보여 주는 상태(Context).
  새 메시지는 바로 붙지 않는다. 검색으로 이동한 대화(`purpose: "search"`)와 읽은 위치로 이동한
  대화(`purpose: "entry"`)가 있다.
- 최신 대화로 돌아감: 이동한 대화를 끝내고 다시 최신 대화를 보여 주는 것.
- 최신 페이지: 방에 들어올 때 최신 대화가 처음 불러오는 최신 메시지 50개.
- 첫 안 읽은 메시지: 읽은 위치 바로 다음 메시지.
- 안 읽은 구분선: 화면의 "여기까지 읽었습니다" 표시.
- 목록 맨 아래에 붙어 있는 상태: 화면이 메시지 목록의 맨 아래에 있어 아래에 메시지가 붙으면 자동으로
  따라 내려가는 상태. 최신 대화에서는 최신 메시지를, 이동한 대화에서는 지금까지 불러온 마지막 메시지를
  보는 상태다.

## 바꾸기 전 구조와 문제

- 진입하면 최신 50개를 불러오고 읽은 위치가 없으면 50개씩 거슬러 찾았다
  (`searchChatRoomEntryHistory`). 자동으로는 최대 5페이지까지만 찾고, 넘으면 사용자에게 계속 찾을지
  물었다. 4단계에서 이 탐색을 없앴다.
- 안 읽은 메시지가 약 300개를 넘으면 읽은 위치로 바로 가지 못하고 안내에서 멈춘다. 자주 생기지는
  않지만 큰 방이나 오래 비운 방에서는 생긴다.
- 검색 결과로 이동할 때 쓰는 이동한 대화(Context, `use-room-message-context.ts`)이 있지만 다음이
  갖춰져 있지 않았다.
  - viewport에서 위·아래로 더 불러오기. hook에는 `loadOlder`/`loadNewer`가 있었지만 화면에 연결되지
    않았고, Context에서는 `canLoadOlder`가 항상 `false`였다. 2단계에서 연결했다.
  - 아래로 불러오다 최신에 닿았을 때 최신 대화로 돌아가기.
  - Context에 있는 동안 내가 보낸 메시지 표시. 전송 대기 메시지를 숨기고 최신으로 이동하지 않는다.
- 채팅방 화면이 쓰는 `useRoomMessageNavigation`은 검색 세션 값을 0으로 고정하므로 Context는 검색과
  무관하게 메시지 ID만으로 열 수 있다(`openContext`).

## 백엔드 계약 (2026-10-23 확인)

- `GET /rooms/{roomId}/messages?afterSequence=N&limit=L`은 일반 순방향 cursor 조회다. `limit`은
  1~100(기본 50)이고, 다음 페이지는 `nextAfterSequence`로 요청하며 `hasMore=false`이면 끝이다. 시작
  위치와 상관없이 비용이 일정하고 이력 조회에는 rate limit이 없다.
- 받아 둔 메시지의 수정·삭제는 cursor로 따라잡을 수 없으므로 WS 이벤트를 `messageVersion` 기준으로
  병합한다.
- 읽음 보고 `throughSequence`는 "이 순번까지 읽음"을 뜻하는 누적값이고 앞으로만 간다. 현재보다 크면
  저장하고(`updated=true`), 같거나 작으면 그대로 두고 200, `updated=false`로 응답한다. 화면에는
  응답의 `readThroughSequence`를 반영한다. 최신 순번보다 크면 409 `READ_SEQUENCE_AHEAD`다. 중간을
  건너뛴 개별 메시지 읽음은 지원하지 않는다.

프론트 계약 코드(`chat-message-contracts.ts`, `chat-read-state-contracts.ts`, 읽음 coordinator)는 이미
위 계약과 맞으므로 백엔드 변경은 필요하지 않다.

## 결정

1. 최신 페이지 안에 읽은 위치가 있으면 지금처럼 그 자리로 이동한다. 없으면 거슬러 찾지 않고 첫 안 읽은
   메시지 위치로 바로 연다. 페이지 한도와 계속 찾기 안내는 없앤다.
2. 읽은 위치로 이동한 대화에서 아래로 불러오다 최신에 닿으면 화면 위치를 유지한 채 최신 대화로 돌아간다.
3. 읽은 위치로 이동한 대화에 있는 동안 하단 버튼은 "최신 대화로 이동"으로 보여 준다. 내가 메시지를 보내면 최신
   대화로 돌아가고 하단으로 이동한다.
4. 읽음 보고 규칙은 최신 대화와 읽은 위치로 이동한 대화에 같은 규칙 하나를 쓴다(아래 읽음 보고 정책).
5. 재참여로 볼 수 있는 경계가 읽은 순번보다 뒤면 경계부터 연다. 현재 `entryReadThroughSequence` 계산을
   그대로 쓴다.
6. 바로 이동 조회가 실패하면 최신 대화를 보여 주고 읽은 위치를 불러오지 못했다는 안내와 재시도를
   띄운다.
7. "최신 대화로 이동"으로 중간을 건너뛰면 최신이 보이는 순간 전부 읽음으로 처리한다. 읽은 순번은
   줄어들지 않는다.

## 진입 흐름

| 단계           | 조건                             | 처리                                                                          |
| -------------- | -------------------------------- | ----------------------------------------------------------------------------- |
| 최신           | 안 읽은 메시지 없음              | 최신 대화, 최신으로 이동                                                      |
| 최신 페이지 안 | 읽은 위치가 최신 페이지에 있음   | 최신 대화, 안 읽은 구분선으로 이동                                            |
| 바로 이동      | 읽은 위치가 최신 페이지보다 이전 | 첫 안 읽은 메시지 조회 후 읽은 위치로 이동한 대화를 보여 주고 구분선으로 이동 |
| 실패           | 첫 안 읽은 메시지 조회 실패      | 최신 대화, 최신으로 이동, 안내와 재시도                                       |

- 첫 안 읽은 메시지는 `afterSequence=읽은 위치, limit=1`로 찾는다. 결과가 없으면 안 읽은 메시지가 없는
  것으로 보고 최신으로 연다.
- 읽은 위치로 이동한 대화는 그 메시지 ID로 Context를 여는 방식으로 만든다. 이렇게 해야 WS 수정·삭제 반영
  (`chat-room-message-search-cache-effects.ts`)과 `messageVersion` 병합을 그대로 받는다. 순번 기준 조회로
  별도 목록을 만들면 WS 이벤트가 닿지 않는다.
- 진입에서도 `openContext(messageId, "entry")`로 같은 Context를 연다. Context는 연 용도(`purpose`)를
  기억하고, 읽은 위치로 이동한 대화는 검색으로 이동한 대화와 달리 안 읽은 구분선을 보여 주고 구분선 위치에서 시작하며
  읽음을 보고한다. 대상 메시지 강조는 하지 않는다.
- 최신 페이지 안에 읽은 위치가 있는지는 `inspectChatRoomEntryHistory`가 판단한다. 진입 상태는
  `use-chat-room-entry-navigation.ts`가 `pending`, `jumping`, `ready`, `error`로 관리한다.
- 첫 안 읽은 메시지를 찾으면 진입 상태를 바꾸는 자리에서 바로 Context를 연다. effect로 나중에 열면 그
  사이 한 번의 렌더 동안 최신 대화가 읽음 보고가 켜진 채 보여 최신까지 읽음 처리될 수 있다.
- 조회가 실패하면 최신 메시지를 보여 주되 다시 찾을 때까지 읽음을 올리지 않는다. "마지막으로 읽은
  위치를 찾지 못했습니다" 안내와 "읽은 위치 다시 찾기" 버튼을 띄운다.

## 이동한 대화 동작

- 위로 스크롤하면 이전 페이지를, 아래로 스크롤하면 다음 페이지를 불러온다. 위쪽은 기존 과거 이력
  anchor 복원을 쓴다. 아래쪽은 목록 끝에 붙으므로 `scrollTop`을 보정하지 않는다.
- 아래쪽 페이지로 붙는 메시지는 새로 도착한 메시지가 아니다. Context에서는 viewport의 `appendMode`를
  `history`로 두어 추가 메시지 감지가 새 메시지 개수, 도착 안내, 최신 따라가기를 하지 않는다. 대신 위치
  모델에 `newer-page-appended`를 보내 하단 고정을 풀고 하단 보정 이동을 멈춘다. 그렇지 않으면 하단
  근처에서 불러온 페이지를 따라 맨 아래로 끌려가며 끝까지 연달아 불러온다.
- 위·아래 페이지 불러오기가 실패하면 이동한 대화 전체를 오류 화면으로 바꾸지 않고 목록 위·아래에 불러오지
  못했다는 안내와 다시 시도 버튼을 띄운다. 오류 화면은 Context 자체를 열지 못했을 때만 쓴다.
- 실시간으로 도착한 새 메시지는 이동한 대화에 붙이지 않는다. 다음 페이지를 불러올 때 함께 온다.
- 마지막 페이지(`hasMore=false`)를 받으면 최신과 이어진 것이다. 이때 화면 맨 위 메시지와 그 높이를
  기억하고 최신 대화로 돌아간 뒤 같은 메시지를 같은 높이에 다시 놓는다. 최신 대화는 진입 목표
  `anchor`(`renderKey`, `offsetFromViewportTop`)로 열린다. 최신 대화의 위쪽은 기존 과거 이력 불러오기로
  다시 볼 수 있다.
- 최신 대화로 돌아갈지는 더 불러올 다음 페이지가 없어졌을 때와 스크롤할 때 확인한다. 위치가 정해져 있고 진행 중인
  자동 이동이 없어야 한다. 기억한 메시지가 최신 대화에 아직 없으면 같은 위치로 되살릴 수 없으므로
  돌아가지 않고 더 내려올 때까지 기다린다.
- 내가 메시지를 보내면 최신 대화로 돌아가고 최신으로 이동한다. 메시지 입력창의 `onSent`를 채팅방
  화면이 받아 Context를 닫고 최신 대화를 진입 목표 `latest`로 연다.
- 최신 대화로 돌아갈 위치는 `use-chat-room-content-experience.ts`가 방·세대별로 기억한다. "최신 대화로
  이동" 버튼은 기존처럼 위치 모델의 최신 이동 의도(`intent=latest`)로 처리한다.

## 읽음 보고 정책

- 메시지 본문의 마지막 줄이 화면에 보이거나 이미 위로 지나갔으면 읽은 것으로 본다. 화면보다 긴
  메시지도 마지막 줄까지 보면 읽음이 된다.
- 보고 값은 위 조건을 만족하는 메시지 중 가장 아래 메시지의 순번이다. 화면 근처에 렌더링된 메시지의
  본문 말풍선(`data-message-bubble`) 위치를 목록 영역과 비교해 계산한다. 가상화 좌표에는 목록 위쪽
  여백과 안내 문구 높이가 빠져 있어 쓰지 않는다.
- 이미 확정된 값보다 작거나 같으면 보내지 않는다. 위로 다시 스크롤해도 읽은 순번은 줄어들지 않는다.
  coordinator가 확정·전송 중·대기 중인 값보다 작거나 같은 값을 거르고 400ms 동안 모아 보낸다. 방에
  들어올 때 서버에 저장된 읽음 순번을 coordinator 확정값으로 올려 둔다.
- 최신 대화와 읽은 위치로 이동한 대화에서만 보고한다. 읽은 위치로 이동한 대화는 읽은 위치부터 끊김 없이 이어져 있으므로
  가장 아래 순번까지 읽은 것으로 볼 수 있다. 검색으로 이동한 대화는 지금처럼 보고하지 않는다.
- 위치가 확정된 상태(`phase=settled`), 창이 보이고 포커스가 있고 overlay가 없을 때만 보고한다.
- 스크롤할 때, 목록이 바뀔 때, 자동 이동이 끝날 때, 포커스·visibility가 돌아왔을 때 다시 계산한다.
- 최신에서는 가장 아래 메시지가 최신이므로 지금 규칙(최신이 보이고 하단 고정일 때 보고)과 결과가 같다.
  하단에서 떨어져 안 읽은 메시지를 읽는 중에도 진행만큼 보고되는 점이 달라진다.
- 안 읽은 구분선은 방에 머무는 동안 진입 때 위치에 고정한다.

## 진행 순서

1. 읽음 보고 규칙 교체 (완료): 최신 대화에 아래 끝 기준 보고를 먼저 적용한다. 진입 흐름과 독립적이고 기존
   읽음 e2e로 검증할 수 있다.
2. Context 확장 (완료): viewport의 위·아래 불러오기를 Context에 연결한다. 이력 페이지와 실시간 추가를
   구분하고 페이지 실패는 목록 위·아래의 다시 시도 안내로 보여 준다. 검색으로 이동한 대화도 위·아래로 더 볼
   수 있게 된다.
3. 최신 대화로 돌아가기 (완료): 마지막 페이지에서 보던 위치를 유지한 채 최신 대화로 돌아간다. 내 메시지
   전송 시 전환도 함께 넣는다.
4. 진입 흐름 교체 (완료): 거슬러 찾기를 바로 이동으로 바꾸고 읽은 위치로 이동한 대화에서 읽음 보고를 켠다. 실패
   안내를 연결하고 사용하지 않는 탐색 코드를 정리한다.

각 단계는 동작이 바뀌는 부분을 커밋에 남기고 `pnpm check`와 관련 e2e를 통과한 뒤 커밋한다.

## 검증

- 단위 테스트: 아래 끝 기준 읽음 순번 계산, 작은 순번 미전송, 진입 단계 판정, Context 페이지 병합,
  최신 대화로 돌아가기 판정.
- 기존 e2e 점검: `chat-read-receipts`, `chat-read-state-reliability`, `chat-room-inbox`,
  `chat-message-search`, `chat-message-viewport*`.
- 바꿀 e2e: `chat-room-entry-navigation.spec.ts`는 현재 최대 5페이지 탐색과 계속 찾기를 검증하므로 바로
  이동 흐름으로 바꾼다.
- 새 e2e: 안 읽은 메시지가 한 페이지(50개)를 넘는 방에 재진입하면 구분선 위치로 바로 열리고, 아래로
  읽으면 읽음이 진행되며, 최신에 닿으면 최신 대화로 돌아가는지 확인한다. 전송량 제한 때문에 짧은
  메시지를 사용한다.

## 범위 밖

- 중간을 건너뛴 개별 메시지 읽음(백엔드 미지원).
- 이동한 대화에 새 메시지를 바로 붙이는 것.
- 가상화 라이브러리 교체와 행 높이 추정값 조정.
