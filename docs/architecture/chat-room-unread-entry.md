# Chat room 재진입 읽은 위치 이동

참여 중인 채팅방 화면에 다시 들어올 때 마지막으로 읽은 위치를 여는 흐름과 읽음 보고 정책을 기록한다.
메시지 viewport의 스크롤 위치 모델은 `chat-message-viewport.md`를 따른다. 구현이 이 문서와 달라지면
문서를 함께 갱신한다.

## 용어

- 재진입: 이미 참여 중인 방을 목록이나 알림에서 다시 여는 화면 진입. 멤버십은 바뀌지 않는다.
- 재참여: 방을 나갔다가 다시 참여하는 것. 볼 수 있는 메시지가 새 참여 시점 이후로 바뀐다
  (`messageVisibleAfterSequence`).
- 읽은 위치: 서버에 저장된 마지막으로 읽은 순번(`storedLastReadSequence`)과 볼 수 있는 경계 중 더
  뒤쪽 순번. 현재 `resolveChatRoomEntryReadPosition`이 `entryReadThroughSequence`로 계산한다.
- 재진입 구간: 읽은 위치 근처를 최신과 떨어져서 보여 주는 메시지 목록.

## 현재 구조와 문제

- 진입하면 최신 50개를 불러오고 읽은 위치가 없으면 50개씩 거슬러 찾는다
  (`searchChatRoomEntryHistory`). 자동으로는 최대 5페이지(`CHAT_ROOM_ENTRY_HISTORY_MAX_AUTOMATIC_PAGES`)
  까지만 찾고, 넘으면 사용자에게 계속 찾을지 묻는다.
- 안 읽은 메시지가 약 300개를 넘으면 읽은 위치로 바로 가지 못하고 안내에서 멈춘다. 자주 생기지는
  않지만 큰 방이나 오래 비운 방에서는 생긴다.
- 검색 결과로 이동할 때 쓰는 최신과 떨어진 구간(Context, `use-room-message-context.ts`)이 있지만 다음이
  갖춰져 있지 않다.
  - viewport에서 위·아래로 더 불러오기. hook에는 `loadOlder`/`loadNewer`가 있지만 화면에 연결되지
    않았고, Context에서는 `canLoadOlder`가 항상 `false`다.
  - 아래로 불러오다 최신에 닿았을 때 실시간 목록과 합치기.
  - Context에 있는 동안 내가 보낸 메시지 표시. 전송 대기 메시지를 숨기고 최신으로 이동하지 않는다.
  - Context는 검색 세션(`searchSessionGeneration`)에 묶여 있다.

## 백엔드 계약 (2026-10-23 확인)

- `GET /rooms/{roomId}/messages?afterSequence=N&limit=L`은 일반 순방향 cursor 조회다. `limit`은
  1~100(기본 50)이고, 다음 페이지는 `nextAfterSequence`로 요청하며 `hasMore=false`이면 끝이다. 시작
  위치와 상관없이 비용이 일정하고 이력 조회에는 rate limit이 없다.
- 받아 둔 메시지의 수정·삭제는 cursor로 따라잡을 수 없으므로 WS 이벤트를 `messageVersion` 기준으로
  병합한다.
- 읽음 보고 `throughSequence`는 "이 순번까지 읽음"을 뜻하는 누적값이고 앞으로만 간다. 현재보다 크면
  저장하고(`updated=true`), 같거나 작으면 그대로 두고 200, `updated=false`로 응답한다. 화면에는
  응답의 `readThroughSequence`를 반영한다. 최신 순번보다 크면 409 `READ_SEQUENCE_AHEAD`다. 중간을
  건너뛴 개별 메시지 읽음은 지원하지 않는다.

프론트 계약 코드(`chat-message-contracts.ts`, `chat-read-state-contracts.ts`, 읽음 coordinator)는 이미
위 계약과 맞으므로 백엔드 변경은 필요하지 않다.

## 결정

1. 최신 페이지 안에 읽은 위치가 있으면 지금처럼 그 자리로 이동한다. 없으면 거슬러 찾지 않고 첫 안 읽은
   메시지 위치로 바로 연다. 페이지 한도와 계속 찾기 안내는 없앤다.
2. 재진입 구간에서 아래로 불러오다 최신에 닿으면 화면 위치를 유지한 채 실시간 목록으로 바꾼다.
3. 재진입 구간에 있는 동안 하단 버튼은 "최신 대화로 이동"으로 보여 준다. 내가 메시지를 보내면 실시간
   목록으로 바꾸고 하단으로 이동한다.
4. 읽음 보고 규칙은 실시간 목록과 재진입 구간에 같은 규칙 하나를 쓴다(아래 읽음 보고 정책).
5. 재참여로 볼 수 있는 경계가 읽은 순번보다 뒤면 경계부터 연다. 현재 `entryReadThroughSequence` 계산을
   그대로 쓴다.
6. 바로 이동 조회가 실패하면 실시간 목록을 보여 주고 읽은 위치를 불러오지 못했다는 안내와 재시도를
   띄운다.
7. "최신 대화로 이동"으로 중간을 건너뛰면 최신이 보이는 순간 전부 읽음으로 처리한다. 읽은 순번은
   줄어들지 않는다.

## 진입 흐름

| 단계           | 조건                             | 처리                                                           |
| -------------- | -------------------------------- | -------------------------------------------------------------- |
| 최신           | 안 읽은 메시지 없음              | 실시간 목록, 최신으로 이동                                     |
| 최신 페이지 안 | 읽은 위치가 최신 페이지에 있음   | 실시간 목록, 안 읽은 구분선으로 이동                           |
| 바로 이동      | 읽은 위치가 최신 페이지보다 이전 | 첫 안 읽은 메시지 조회 후 재진입 구간으로 열고 구분선으로 이동 |
| 실패           | 첫 안 읽은 메시지 조회 실패      | 실시간 목록, 최신으로 이동, 안내와 재시도                      |

- 첫 안 읽은 메시지는 `afterSequence=읽은 위치, limit=1`로 찾는다. 결과가 없으면 안 읽은 메시지가 없는
  것으로 보고 최신으로 연다.
- 재진입 구간은 그 메시지 ID로 Context를 여는 방식으로 만든다. 이렇게 해야 WS 수정·삭제 반영
  (`chat-room-message-search-cache-effects.ts`)과 `messageVersion` 병합을 그대로 받는다. 순번 기준 조회로
  별도 목록을 만들면 WS 이벤트가 닿지 않는다.
- Context를 검색 세션에서 분리해 진입에서도 열 수 있게 한다. 검색 결과 구간과 재진입 구간은 같은
  구조를 쓰고, 읽음 보고 여부만 다르다.

## 재진입 구간 동작

- 위로 스크롤하면 이전 페이지를, 아래로 스크롤하면 다음 페이지를 불러온다. 위쪽은 기존 과거 이력
  anchor 복원을 쓴다. 아래쪽은 목록 끝에 붙으므로 `scrollTop`을 보정하지 않는다.
- 아래쪽 페이지로 붙는 메시지는 새로 도착한 메시지가 아니다. viewport의 추가 메시지 감지가 이를 실시간
  추가로 보고 새 메시지 개수를 세거나 최신을 따라가지 않도록, 재진입 구간에서는 이력 페이지와 실시간
  추가를 구분한다.
- 실시간으로 도착한 새 메시지는 재진입 구간에 붙이지 않는다. 다음 페이지를 불러올 때 함께 온다.
- 마지막 페이지(`hasMore=false`)를 받으면 최신과 이어진 것이다. 이때 화면 맨 위 항목을 anchor로 잡고
  실시간 목록으로 바꾼 뒤 같은 항목을 같은 위치에 복원한다. 화면 근처 항목은 최신 페이지 안에 있으므로
  복원할 수 있다. 실시간 목록의 위쪽은 기존 과거 이력 불러오기로 다시 볼 수 있다.
- 내가 메시지를 보내면 실시간 목록으로 바꾸고 최신으로 이동한다.

## 읽음 보고 정책

- 메시지의 아래 끝이 목록 영역의 아래 경계 안으로 들어오면 읽은 것으로 본다. 화면보다 긴 메시지도
  마지막 줄까지 보면 읽음이 된다. 이미 위로 지나간 메시지도 읽음이다.
- 보고 값은 위 조건을 만족하는 메시지 중 가장 아래 메시지의 순번이다. 가상화 항목의 위치
  (`start + size`)와 `scrollTop + clientHeight`를 비교해 DOM을 읽지 않고 계산한다.
- 이미 확정된 값보다 작거나 같으면 보내지 않는다. 위로 다시 스크롤해도 읽은 순번은 줄어들지 않는다.
  백엔드와 coordinator도 큰 값만 남긴다.
- 실시간 목록과 재진입 구간에서만 보고한다. 재진입 구간은 읽은 위치부터 끊김 없이 이어져 있으므로
  가장 아래 순번까지 읽은 것으로 볼 수 있다. 검색 결과로 건너뛴 구간은 지금처럼 보고하지 않는다.
- 위치가 확정된 상태(`phase=settled`), 창이 보이고 포커스가 있고 overlay가 없을 때만 보고한다.
- 스크롤이 멈출 때, 페이지를 더 불러왔을 때, 포커스·visibility가 돌아왔을 때 다시 계산한다.
- 최신에서는 가장 아래 메시지가 최신이므로 지금 규칙(최신이 보이고 하단 고정일 때 보고)과 결과가 같다.
  하단에서 떨어져 안 읽은 메시지를 읽는 중에도 진행만큼 보고되는 점이 달라진다.
- 안 읽은 구분선은 방에 머무는 동안 진입 때 위치에 고정한다.

## 진행 순서

1. 읽음 보고 규칙 교체: 실시간 목록에 아래 끝 기준 보고를 먼저 적용한다. 진입 흐름과 독립적이고 기존
   읽음 e2e로 검증할 수 있다.
2. Context 확장: 검색 세션에서 분리하고 viewport의 위·아래 불러오기를 연결한다. 이력 페이지와 실시간
   추가를 구분한다. 검색 결과 구간도 위·아래로 더 볼 수 있게 된다.
3. 최신과 합치기: 마지막 페이지에서 anchor를 유지한 채 실시간 목록으로 바꾼다. 내 메시지 전송 시 전환도
   함께 넣는다.
4. 진입 흐름 교체: 거슬러 찾기를 바로 이동으로 바꾸고 재진입 구간에서 읽음 보고를 켠다. 실패 안내를
   연결하고 사용하지 않는 탐색 코드를 정리한다.

각 단계는 동작이 바뀌는 부분을 커밋에 남기고 `pnpm check`와 관련 e2e를 통과한 뒤 커밋한다.

## 검증

- 단위 테스트: 아래 끝 기준 읽음 순번 계산, 작은 순번 미전송, 진입 단계 판정, Context 페이지 병합,
  최신 합치기 판정.
- 기존 e2e 점검: `chat-read-receipts`, `chat-read-state-reliability`, `chat-room-inbox`,
  `chat-message-search`, `chat-message-viewport*`.
- 바꿀 e2e: `chat-room-entry-navigation.spec.ts`는 현재 최대 5페이지 탐색과 계속 찾기를 검증하므로 바로
  이동 흐름으로 바꾼다.
- 새 e2e: 안 읽은 메시지가 한 페이지(50개)를 넘는 방에 재진입하면 구분선 위치로 바로 열리고, 아래로
  읽으면 읽음이 진행되며, 최신에 닿으면 실시간 목록으로 이어지는지 확인한다. 전송량 제한 때문에 짧은
  메시지를 사용한다.

## 범위 밖

- 중간을 건너뛴 개별 메시지 읽음(백엔드 미지원).
- 재진입 구간에 실시간 새 메시지를 바로 붙이는 것.
- 가상화 라이브러리 교체와 행 높이 추정값 조정.
